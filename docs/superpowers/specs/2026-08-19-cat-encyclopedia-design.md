# 猫咪图鉴页面设计

## 目标

将现有 Cocos Creator 游戏中的 `CollectionView` 重做为设计稿对应的猫咪图鉴页面。页面必须接入现有 `Cat2048Boot` 导航、解锁存档和猫咪资源加载流程，沿用 `GAME_CONFIG.cats` 的 12 只猫咪，不改变玩法数据。

## 页面结构

- 使用现有 750x1334 设计坐标和安全区布局。
- 页面背景为暖奶油纸张，外围仅保留稀疏的手绘爪印、星星、弧线和叶片装饰，保持与设计稿的奶油色、棕色描边、青绿色进度条一致。
- 顶部显示左上角爪垫返回按钮、居中的“猫咪图鉴”标题和“已解锁 x/12”进度条。
- 中部显示三列猫咪卡片，卡片区域可纵向滚动，并在底部安全区前裁剪。
- 图鉴页不显示底部导航栏；页面离开通过左上角爪垫按钮完成。
- 卡片不响应点击，也不打开详情弹窗；已解锁卡片显示猫咪资源、等级和现有中文名，未解锁卡片显示锁定猫剪影、锁图标、等级和“未解锁”。

## 资源策略

- 使用项目内 `skills/generate-kitchen-game-art` 生成页面背景、浅色卡面、锁定卡面、返回爪垫、锁定猫剪影和锁图标；资源清单、提示词和生成报告保留在 `assets/collection-v2/`。
- 将生成的最终 PNG 导入/复制到 Cocos `resources` 可加载路径，并在 `ArtRepository` 中增加对应 frame 路径。
- 中文标题、等级、名称和解锁计数由 Cocos `Label` 叠加，避免图像模型生成中文文字失真；进度填充继续使用现有 `Graphics` 绘制。
- 已解锁猫咪继续从 `GAME_CONFIG.cats` 与 `CosmeticRuntime.catFrame()` 获取，确保皮肤和存档逻辑不变。

## 组件和数据流

- `Cat2048Boot.showCollection()` 继续负责加载猫咪资源并调用渲染。
- `CollectionView.build()` 接收现有 `CollectionViewModel` 与 `CollectionActions`，不新增持久化状态。
- `CollectionView` 负责标题、进度条、滚动视口和静态卡片；移除详情弹窗、卡片触摸事件和 `BottomNavigation` 的构造及渲染。
- 返回、音效、设置等底部导航操作不再出现在图鉴页；现有 `onBack` 回调保持不变，按来源返回主页或游戏页。

## 交互与适配

- 页面响应窗口尺寸变化，沿用现有安全区计算和滚动视口约束。
- 不改动存档、经济系统、猫咪解锁规则和其他页面。

## 范围外

- 不新增图鉴筛选、排序、分页或联网数据。
- 不实现底部导航栏的新视觉版本。
- 不实现猫咪详情弹窗。
