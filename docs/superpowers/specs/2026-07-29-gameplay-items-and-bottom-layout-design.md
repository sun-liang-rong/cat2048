# 猫咪 2048 棋盘下移与局内道具设计

**日期：** 2026-07-29

**状态：** 已确认，待实施规划

## 1. 目标

减少高屏设备游戏页底部的无效空白，把棋盘移入更适合单手滑动的区域，并在棋盘下方增加两个真实可用的局内道具：撤回一步、消除 3 个最低等级猫咪。

## 2. 布局

采用方案 A：顶部返回、本局分数、最高分和重新开始区域保持现有层级；棋盘整体向下移动；棋盘下方紧接双按钮道具栏；删除现有的玩法说明文字。

布局由纯 TypeScript 的 `gameLayout` 统一计算：

- 高屏设备优先保持棋盘原尺寸，并将棋盘和道具栏组成的操作区放入屏幕下半部。
- 矮屏设备按可用高度等比缩小棋盘，不能让顶部 HUD、棋盘、道具栏或底部安全区相互覆盖。
- 道具栏始终位于棋盘下方，按钮触控区域不小于 88 个设计单位高。
- 道具栏下边缘必须高于设备底部安全区。

## 3. 道具规则

### 3.1 撤回一步

- 每局可使用 1 次，新开一局时恢复。
- 仅保存最近一次有效滑动之前的棋盘和分数。
- 无可撤回步骤时按钮保持禁用，且不会消耗次数。
- 使用后恢复棋盘和分数，不生成新猫，不播放移动合并流程。
- 道具操作本身不产生新的撤回记录，不能撤回另一个道具操作。
- 一旦使用，按钮显示剩余 `0` 并置灰。

### 3.2 消除 3 个最低等级猫咪

- 每局可使用 1 次，新开一局时恢复。
- 从当前棋盘按等级由低到高选择猫咪；同等级按从上到下、从左到右选择。
- 最多消除 3 只；棋盘不足 3 只时全部消除。
- 空棋盘上使用时不消耗次数。
- 使用后不生成新猫、不改变分数；即使棋盘变空，游戏仍保持运行。
- 一旦成功使用，按钮显示剩余 `0` 并置灰。

## 4. 状态与核心接口

道具结果必须由纯 TypeScript 游戏核心生成，展示层不能直接修改棋盘：

- 游戏核心在每次有效移动前保留一个不可变快照，内容包括棋盘和分数。
- `undo()` 返回是否生效以及恢复后的棋盘、分数和游戏状态。
- `removeLowestTiles(3)` 返回是否生效、被移除的 tile ID、更新后的棋盘、分数和游戏状态。
- `start()` 清除撤回快照并重置两种道具的局内次数。
- 无效滑动不覆盖已有的撤回快照。

道具次数属于当前对局的运行时状态，不写入本地存档。最高分和音效存档结构保持不变。

## 5. 展示与交互

- 道具按钮采用现有暖色木质、奶油色和青绿色视觉体系，分别显示图标/短标题以及剩余次数。
- 可用状态具有清晰描边和按压反馈；不可用状态降低饱和度与透明度，并阻止点击。
- 点击可用道具后立即锁定棋盘和按钮输入，完成反馈动画后解锁。
- 撤回使用短促的整体棋盘淡出/恢复反馈；消除对目标猫咪播放依次缩小淡出，再同步渲染棋盘。
- 道具操作完成后更新分数与按钮状态；最高分不会因撤回而降低。
- 重新开始、返回主页和游戏结束弹窗继续使用现有流程。

## 6. 测试与验收

纯 TypeScript 单元测试覆盖：

- 撤回恢复最近一次有效移动前的棋盘和分数。
- 无效移动不替换撤回记录。
- 无历史和已使用状态不能撤回，也不错误消耗次数。
- 消除选择最低等级，并对同等级使用稳定的行列顺序。
- 少于 3 只、空棋盘以及消除后空棋盘的行为。
- 两个道具每局各一次，并在 `start()` 后恢复。

布局测试覆盖代表性 `750 × 1100` 和 `750 × 1600` 设计空间，验证 HUD、棋盘、道具栏和安全区不重叠，并验证高屏棋盘位置比当前布局更低。

最终验收要求：高屏设备下棋盘明显进入单手舒适区；两个道具按钮始终完整可见且可点击；道具规则、次数、动画锁和新局重置符合本文定义；现有 2048、存档、资源与布局测试无回归。
