# 震动设置设计

## 目标

在现有设置弹窗中增加独立的“震动”开关。震动默认开启，玩家关闭后，游戏中的合并和道具操作不再触发平台震动。

## 界面与交互

- 保留主页现有的设置入口和音效快捷按钮。
- 将当前只控制音效的设置弹窗改为设置面板。
- 面板包含“音效”和“震动”两行，每行展示当前状态及一个可点击开关。
- 点击任一开关后立即更新界面和本地设置，不关闭弹窗。
- 弹窗保留关闭按钮，关闭后返回主页。

## 数据与兼容性

- 存档增加布尔字段 `hapticsEnabled`，默认值为 `true`。
- 已包含该字段的存档直接读取。
- 旧 V1 存档缺少该字段时补为 `true`，同时保留最高分和音效设置，避免升级导致数据重置。
- 开关变化立即写入本地存储。

## 震动逻辑

- `HapticController` 增加启用状态；禁用时所有震动方法直接返回，不调用微信或浏览器震动 API。
- 游戏加载存档后将 `hapticsEnabled` 同步到控制器。
- 设置面板切换震动时同时更新存档和控制器状态。
- 保持现有震动触发范围：猫咪合并和道具操作。普通移动不新增震动。

## 容错

- 平台不支持震动时保持静默，不影响游戏。
- 平台震动 API 抛错时延续现有降级行为，只记录警告，不中断操作。
- 本地存储不可用时继续使用内存中的设置状态。

## 测试

- 存档测试覆盖默认开启、旧存档补全字段、完整存档读取和非法数据修复。
- 控制器测试覆盖关闭后不调用平台 API、重新开启后恢复调用。
- 类型检查覆盖设置字段在游戏代码中的使用。
